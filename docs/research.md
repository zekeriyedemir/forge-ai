# Live Research Agent

Set `DEMO_MODE=false`, `OPENAI_API_KEY`, and `BRAVE_SEARCH_API_KEY` as private server environment variables. The Brave key uses the [Web Search API](https://api-dashboard.search.brave.com/api-reference/web/search/get) `X-Subscription-Token` header; Forge calls the fixed `https://api.search.brave.com/res/v1/web/search` endpoint. Goal-derived queries are sent to Brave, and bounded retrieved excerpts are sent to the configured AI provider; use a goal that is appropriate to share with those services. The OpenAI-compatible model must support Chat Completions JSON mode and a 4,096-token completion budget. No real provider call is made by the automated suite.

When configured, the existing workflow's Research step issues five goal-related search queries covering market demand, competitors/pricing, customer pain and segments, positioning/opportunities, and distribution. It considers at most two hits per query and retrieves at most six distinct pages, sampling each query before taking additional hits. Each page must be public HTTPS HTML. DNS answers are restricted to public IPv4, the validated address is pinned for the connection, and each redirect is checked anew. Page transfers stop at 64 KiB; saved visible excerpts stop at 12,000 characters, with at most 6,000 characters per source sent to the model. Search responses stop at 96 KiB. Search requests time out after eight seconds, DNS after three seconds, page requests after five seconds, and AI synthesis has one bounded repair attempt. Failed pages are excluded and noted as a limitation; no retrievable pages means no findings.

The model receives only bounded, untrusted excerpts and returns a structured summary, limitations, and at most eight findings. Each finding identifies one saved source index and an exact 15–300 character quote that must appear in that source's excerpt. Unsupported citations, malformed output, and invented quote text are rejected. Quotes demonstrate where a statement came from; they do not independently prove that the source or model interpretation is correct. Confidence is restricted to low or medium. The report contains numbered source URLs and retrieval timestamps. Users can inspect every finding, quote, source URL, and saved excerpt in **Project → Research**. The second Founder pass receives only the completed session's findings from the same workflow.

The UI labels live sessions **COMPLETED** or **FAILED**. A completed session means the provider returned pages and Forge validated its source quotes; it is not a claim that every market conclusion is true. With `DEMO_MODE=true`, the old deterministic research outline is **MOCKED** and no live evidence session is made. With `DEMO_MODE=false` and either key missing, research is **NOT CONFIGURED** and the run fails visibly. Server credentials, raw model completions, and full page bodies are never exposed to the browser or logs.

To verify with your own provider, apply migration `20260917190000_live_research` using `npm run db:migrate` against the intended database, configure both keys privately, start a workflow for a disposable project with a specific goal, and open **Project → Research**. Confirm a completed session has actual external URLs, retrieval times, excerpts, quote-backed findings, and stated limitations; inspect the source pages yourself. Then inspect the second Founder run/report for use of those findings. If the search or model is not configured, confirm the Research run fails with the expected configuration message and no live findings. No production deployment or provider call is performed as part of the automated tests.
