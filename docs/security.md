# Security

Auth.js stores sessions in PostgreSQL and GitHub OAuth credentials stay on the server. A GitHub access token is read from the Account table only inside server code. Repository association re-checks the repository against the authenticated user's GitHub API response; a client-supplied name or URL is never trusted.

Project reads require workspace membership; project mutations require an `OWNER` membership on server actions and API routes. Inaccessible project pages render the not-found boundary; API requests return 404. Goal, task, repository-link, and project-delete writes include the ownership predicate in the database operation. Repository linking and integration status save in one transaction; workspace creation uses serializable isolation with bounded retries to handle concurrent first visits. Forms and tool inputs use Zod. Workflow starts have a database-backed hourly cost guard. Configure a unique `AUTH_SECRET`, HTTPS, and database credentials in the deployment environment.

The public `/demo` is a read-only sample and does not access a database, live AI, or GitHub. `DEMO_MODE=true` permits a shared sample identity only in development/test; it cannot bypass production authentication. Demo mode always uses deterministic planning output and blocks GitHub credential reads, live research synthesis, and Developer proposals even when real keys exist. Keep local demo data disposable and set `DEMO_MODE=false` for authenticated live workspaces.

Developer repository writes require a real authenticated GitHub session, project ownership, an exact linked-repository identity, and a persisted approval. The OAuth app uses the `repo` scope for private/public repository read/write and Actions log access; organization policies can still deny access. GitHub tokens remain server-side and are not sent to the model or browser. Approved source changes are limited to five text files, 32 KB per file, 64 KB total, and a repository tree of at most 500 entries. Model inspection reads at most ten text files, 12 KB each and 64 KB total. Hidden paths, traversal, binary content, credential-like content and paths, and files outside source/test/docs roots are rejected. Existing files may be replaced only if Forge read their full original contents. CREATE and UPDATE are explicit; DELETE is unsupported. Branch writes are restricted to generated `forge/` branches and are never forced. Every CI correction needs a new approval and exact old-head check, with at most three rounds. External feature-branch changes block correction and merge until a project owner explicitly adopts the exact reviewed SHA; adoption itself performs no GitHub write. Prior merge approvals are rejected and a fresh approval is bound to the adopted head. Merge requires a separate approval tied to the current head and passing remote checks.

The repository inspection filters obvious credential material, but no static filter can guarantee that arbitrary source text contains no secrets. Use a repository without committed secrets and review the exact proposal before approval. Forge never reads local `.env` or gives the model access to server environment variables. For failed Actions jobs, Forge reads at most 32 KB from a GitHub-signed log URL without forwarding its OAuth header and derives only diagnostic categories, TypeScript codes, and validated file paths. It never persists or prompts with raw logs, environment values, or the signed URL. Check/job names are shown only if they pass a strict safe-label filter. The GitHub OAuth `repo` scope is broad; a dedicated GitHub App with repository-scoped permissions is a future hardening option. The Developer workflow does not run target code or model-provided commands on the Forge server.

Current limitations: the workflow budget is not a comprehensive account/IP abuse-prevention system, OAuth tokens rely on database and infrastructure encryption controls, and GitHub's OAuth `repo` grant is broader than a repository-scoped GitHub App. Explicit owner review is required for each detected external head. Repository execution requires real GitHub sign-in with demo mode disabled and a live AI provider.

Live Research uses an operator-configured SearXNG service or the fixed Brave Search endpoint with a server-only key. Candidate pages must be public HTTPS hostnames on port 443. Forge resolves IPv4 addresses, rejects private/reserved or mixed DNS answers, pins the validated address for the request, and repeats checks for at most two redirects. It accepts only bounded HTML, strips active tags, and saves at most 12,000 characters per page. Searches/pages and synthesis retries are bounded. Search pages are untrusted input: neither their text nor model output can authorize a tool call. Finding citations require an exact quote present in the retrieved excerpt; this proves provenance of the quote, not the truth of a market conclusion. No raw page content, prompts, keys, or AI completions are logged. See [Research](research.md).

The October 2026 portfolio review checked authentication, project ownership, mutation inputs, GitHub credential handling, external errors, approval boundaries, Prisma relationships, and obvious credential patterns across all tracked files and reachable Git history. No real committed credentials were found; matches were synthetic security-test fixtures, schema declarations, and local CI placeholders. This bounded source review and mocked API testing do not replace a live OAuth/deployment verification or an exhaustive penetration test. `.env` and secret-file patterns are ignored; `.env.example` contains placeholders only.
